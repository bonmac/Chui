# Factory 0.4.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the harness fail closed, make read-only agents read-only in fact, give reviews a
protocol and a place to land, and record what lanes cost, as factory 0.4.0.

**Architecture:** Hook changes stay inside the existing POSIX sh files and their Julia tests. Agent
protocol changes go through `gen.jl` (two body fragments rendered into every agent) and the registry.
The review routine and CI triage become two commands over existing scripts (`lane.jl`, `tdd.jl`,
`ci.jl`, `evidence.jl`). `lane.jl` gains `compact`, `stats` and `handoff`.

**Tech Stack:** POSIX sh + jq hooks; Julia 1.13.2 and 1.10.12 (`julia`, `julia +lts`); the factory
test suite `scripts/test/runtests.jl`; `gh` for CI triage; `runic` (optional) for the format hook.

**Spec:** `docs/superpowers/specs/2026-10-27-factory-040-design.md` (decisions D1–D12, ★ items 1–6)

## Global Constraints

- Paths are under `factory/template/` unless they start with `factory/`, `adr/`, `docs/` or `<root>`.
- Work in a lane: `scripts/lane new f040 --owns 'factory/**,adr/0016*,docs/superpowers/**,changelog.d/f040.md'`.
  Sub-lanes (`f040-hooks`, `f040-agents`, `f040-commands`, `f040-lane`) are siblings with disjoint
  globs taken from each task's **Files**. Never run anything in the reference roots.
- Run the suite from the lane root, never with cwd in `factory/template`:
  `(cd factory/template && julia --startup-file=no scripts/gen.jl --check && julia --startup-file=no scripts/test/runtests.jl)`
  on `julia` and `julia +lts`. Paste both. Unset `FACTORY_ALLOW_T3` and `FACTORY_ALLOW_PUSH` first.
- Size limits (`ratchets.toml`): `.claude/hooks/*.sh` ≤ 150 lines, `scripts/*.jl` ≤ 400 lines,
  `CLAUDE.md` ≤ 150 lines. A hook that would exceed 150 lines splits a sourced `_*.sh` library.
- Change files with Edit/Write only. Each task ends with a Conventional Commit on the lane branch and
  a line in `changelog.d/f040.md`. Tests first: the RED run is pasted before the GREEN run.
- Verdict vocabulary (D5, ★2 decided 2026-10-27): `Verdict: MAY MERGE | MERGE WITH FIXES | FIX FIRST`.
- Report cap (D4, ★4 decided): 80 lines; a command is quoted as command, exit code, last 20 lines.
- ★1 decided: lane f040 started 2026-10-27 from coordinator main while tw-031 (0.3.0) is still open
  in another session; after tw-031 merges and 0.3.0 syncs, f040 is rebased and the rebase reviewed.
  tw-031 rewrites the template settings.json, registry, lane-lifecycle skill, change-review.md,
  dod.jl and the hooks: expect conflicts there. ★3: precedence note only. ★5: the user's hand.
  ★6: `.worktrees/tw-030-verify` is the other session's; only `lead-l0` is removed, with the user.
- Sub-lanes record their change in `changelog.d/<sub-lane>.md`; the lead folds them at Task 10.

## Review Focus

1. A guard killed by SIGTERM mid-run (exit 143) must block, not allow: Task 1 tests exit 143.
2. `lane compact` run while a dispatch is open must keep that dispatch counted afterwards: Task 2 tests
   the count before and after.
3. A read-only agent calling `julia scripts/ci.jl test` must be allowed, but `julia -e 'write(...)'`
   must be denied: Task 3 tests both.
4. A report whose first line is `verdict: may merge` (wrong case) must be rejected, so the enum stays
   mechanical: Task 5 tests it.
5. `lane handoff` with a worktree outside `.worktrees/` must list it as unmanaged, not skip it: Task 9.
