- **factory 0.4.0, final whole-branch review fixes (f040-fix6)** (`factory/template/`; not yet versioned or
  synced). The final review's code findings M1, M2, m3, m4 and n1:
  - M1: no hook append is lost to `scripts/lane compact`. `ledger()` in
    `factory/template/.claude/hooks/_lib.sh` never appends to the ledger without `.lanes/.dispatch.lock`:
    after its ~1 s wait the event goes to `.lanes/ledger.pending.jsonl` (O_APPEND, a separate file).
    `compact!` in `factory/template/scripts/_lane_stats.jl`, under the lock, appends the bytes written to the
    ledger past its read and the pending file to the new ledger before the rename, then folds later pending
    bytes and empties that file. `dispatch_limit.sh`, `lane_ledger.sh`, `precompact.sh` and lane.jl's readers
    (`open_lanes`, `ledger_rows`: stats, handoff, `audit --report`) read ledger + pending. Remaining windows
    are stated in `factory/template/.agents/checks.toml` (lane_ledger).
  - M2: a report file is `<dispatch name>.md` or `<dispatch name>--r<digits>.md` (double dash and `r`), the
    base name matched exactly against the ledger's dispatch names first, no other stripping: `tw-030.md` is
    tw-030's and `reviewer-2.md` is no longer a round of `reviewer`. Applied in `report_name`/`report_dispatch`
    (`_lane_stats.jl`), `factory/template/.claude/hooks/teammate_idle.sh`, `factory/template/.agents/bodies/_report.md` (the
    agent-type fallback is gone: the brief names the dispatch), `_verdict.md`,
    `factory/template/.claude/commands/lane-review.md` and the lane-lifecycle skill.
  - m3: a read-only agent may run `scripts/lane audit` (or `julia scripts/lane.jl audit`) but not with
    `--report`, which appends a ledger `verdict` (`ro_lane_audit`, `factory/template/.claude/hooks/_bash_guard_agents.sh`).
  - m4: `factory/template/.claude/hooks/format_check.sh` exits 0 silently for an agent_type in
    READ_ONLY_AGENTS (it had told the agent to run runic, which its guard refuses).
  - n1: the dispatch lock carries an `owner` token (`dispatch_limit.sh` and lane.jl's `with_lock`); each
    removes the lock only while the token is still its own, and dispatch_limit's stale break ignores the token
    file, so a compact whose lock was broken after a minute no longer removes the hook's new lock.
  - Tests: `factory/template/scripts/test/test_hooks_040b.jl` and `test_lane_040b.jl` (new files: the
    400-line budgets); earlier tests updated for the new report names and the pending file.
