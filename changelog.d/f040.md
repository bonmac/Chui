The harness fails closed, read-only agents are enforced by the hooks, and every review follows one
report protocol (ADR-0016, Accepted by the user 2026-10-27; spec
`docs/superpowers/specs/2026-10-27-factory-040-design.md` D1–D12; plan
`docs/superpowers/plans/2026-10-27-factory-040.md`). A minor bump: the guards are stricter, the
registry has a new required `output_format` ending, and seeded files need hand edits (Migration).
Builds on 0.3.1, merged in before the release; folded into `factory/CHANGELOG.md` as `## 0.4.0` on
top of 0.3.2.

- **Guards fail closed (D1).** The three `settings.json` wrappers exit 2 on ANY non-zero exit of
  `bash_guard.sh`, `write_guard.sh` and `dispatch_limit.sh` (a crash, exit 1, SIGTERM 143), not
  only when the script is missing. `bash_guard.sh` denies when its command splitter fails or
  returns nothing for a non-blank, non-comment command (awk missing or crashed used to pass
  everything). An in-hook watchdog (`_watchdog.sh`, `FACTORY_WATCHDOG_SECS`, default 8 s, inside
  the host's 10 s budget, which fails open) starts before the lock wait and kills a slow step:
  `dispatch_limit`'s count and the TDD dispatch check's two git reads (in both `dispatch_limit.sh`
  and `tdd_boundary.sh`; their output goes to a `mktemp` file, and none can be made: denied). A
  fire logs `guard-timeout` to the pending file. The Bash matcher also covers `Monitor`;
  `MultiEdit` leaves the Edit matcher.
- **The ledger (D2).** `ledger()` (`_lib.sh`) and lane.jl's `ledger_line` never append to the
  ledger directly: each line goes to `ledger.pending.jsonl` beside it, and a holder of
  `.lanes/.dispatch.lock` (waited for about 1 s; `FACTORY_LEDGER_LOCKED=1` for the holder,
  `=pending` for the watchdog) folds it in. Every lock taker (ledger(), dispatch_limit, lane.jl's
  `with_lock`, `lane compact`) folds first, so pending is only ever the ledger's tail and the
  ledger's order is arrival order. A fold renames the pending file, appends it, re-reads it and
  removes it; a crash's leftover `ledger.pending.jsonl.<epoch>.<pid>` folds first (in lexical
  name order). Every reader (dispatch_limit, lane_ledger, precompact, lane.jl, and tdd.jl's E5
  through `ledger_records`) reads the ledger, the leftovers, then pending. The lock dir and the
  pending file are those beside the CURRENT `LEDGER_FILE`, so a `tdd-commit` record for another
  checkout's owning ledger (0.3.1) locks and folds that ledger; `tdd_commit_post` restores the
  session ledger after each entry. The lock carries an owner token: each taker removes only its
  own. `scripts/lane compact [--keep N]` rewrites the ledger under the lock, keeping every
  dispatch, spawn, close, verdict and denial; it drops only orphan `stop`s, non-JSON lines and idle
  events outside the last N (200), and replaces nothing if the open set would change.
  `precompact.sh` runs it detached past `FACTORY_LEDGER_LINES` (default 2000), which
  `dispatch_limit`'s cap denial also names. `lane_ledger.sh` writes a `stop` only for an agent_id
  that a `spawned` or `unknown-result` record names (teammate turns had written 1,043 noise lines);
  `teammate_idle.sh` logs `idle-unreported` once per teammate key.
- **Heredocs.** A heredoc body ends only at a line exactly equal to its WORD (leading tabs
  stripped for `<<-`). `WORD)` never ends one: bash and zsh disagree there, so such a line is
  refused, as is `"$(cat <<EOF)"` on one line ("put the closing ) on its own line"). A bare `cd`
  moves the tracked cwd to `$HOME`.
- **Read-only agents enforced by `agent_type` (D3).** `gen.jl` renders `READ_ONLY_AGENTS` into
  `limits.env` from every `default_mode = "read_only"` agent (critic, reviewer, verifier); a
  `limits.env` without it denies every agent. For such an agent (`_bash_guard_agents.sh`,
  `_bash_guard_agents_lib.sh`, both required):
  - Bash runs only the agents' own list `RO_AGENT_CMDS`, allowed by subcommand: `git` read
    subcommands without `-c`/`--config-env`/`--exec-path`/`--git-dir`/`--work-tree`/`--output`;
    `julia` with only `--startup-file=no` and a `+channel` running the repo's own `dod.jl`,
    `ci.jl {test,guards,quality,docs}`, `evidence.jl`, `test/runtests.jl`, `gen.jl --check`,
    `tdd.jl audit`, `lane.jl audit`; `scripts/lane audit <lane> [--base] [--owns] [--reported]`
    (never `--repo` or `--report`). No output redirection, inline assignment or `--root`.
  - Fixed option sets: `rg`, `sort`, `uniq`, `file`, `less` (and `--hostname-bin` is refused);
    `cp` only `-R -r -p`, `mkdir` only `-p`; `--` ends options; `uniq` takes one operand.
  - Writes (Edit/Write, cp, mkdir) only to `.lanes/reports/**` and `.lanes/scratch/<agent_type>/**`,
    through no symlink at or below the root, with no `.`/`..`, glob or expansion in the raw path; a
    `cp -R` source holding a symlink, or deeper than 8 levels, is refused.
  - Trusted checkouts only: every cwd, `cd`, `git -C` target and script is a literal path in the
    root, its main checkout or a lane worktree of either, never below `.lanes/`.
  - A `.git` component matches case-insensitively (`.GIT`, `.Git` on APFS) for the lead too, and
    for a read-only agent even with `FACTORY_ALLOW_T3=1` in a Write, cp or mkdir target; a cp
    source only when its last component is `.git`.
  - The lead (no `agent_type`) is unchanged. `reviewer` and `critic` gain `Write`; the critic's gate
    audit runs `julia scripts/test/runtests.jl hooks --hooks-dir <scratch copy>` (`runtests.jl`
    now takes `[NAME...] [--hooks-dir DIR]`). New check `read_only_agents`.
- **Report protocol (D4, D5).** Fragments `_preflight.md` (print `pwd`, toplevel, branch, worktree
  list; stop on a mismatch) and `_report.md` are rendered into every agent; `_verdict.md` into the
  read-only agents only. A report is `<session root>/.lanes/reports/<dispatch name>.md` or
  `<name>--r<round>.md`. A read-only agent's line 1 is `Verdict: MAY MERGE | MERGE WITH FIXES | FIX
  FIRST` and line 2 `Head: <sha>`; a write agent's line 1 is `Status: DONE | PARTIAL | BLOCKED`
  (`Verdict: PENDING` / `Status: PARTIAL` while writing). The TDD roles stay unnamed (0.3.1): their
  final reply is the report and the file is optional; a test-side role writes it once. At most 80
  lines, a command quoted with its exit code and last 20 lines. Every `output_format` ends with
  `; at most 80 lines` (`gen.jl --check` fails otherwise). `teammate_idle.sh` accepts either final
  line 1 by exact name. `scripts/lane audit <lane> --report FILE` binds a report to a NAMED
  dispatch of a read-only type (`READ_ONLY_AGENTS`), requires the exact Verdict line, `Head:` on
  line 2 naming the lane's current HEAD and a clean lane, and records a `verdict` in the ledger.
- **Commands (D6, D12).** `/lane-review <lane>`: scope audit, the base-vs-lane test gate through
  `evidence.jl` (mutants for a package; the hook-mutation route for the factory), `ci.jl guards`,
  `dod.jl`, the named `reviewer`, its FINAL report, `lane audit --report`. `/ci-triage [run id]`:
  failed jobs grouped, reproduced with `ci.jl <job> --timeout 900`, labelled
  `guard | flake | defect`. `/change-review` runs `/lane-review` for a lane. The coordinator profile
  no longer gets `/contract-check`, `/release-check`, `/test-changed` ("Package repos only:").
- **Numbers and precedence (D7).** The lane-lifecycle skill names the cap's key, never a number or
  a marker: the number lives once, in each repo's CLAUDE.md `<!-- claim: max_open=N -->`. The
  seeded CLAUDE.md gains "Precedence" (the factory's lane tool, reviewer, critic, cap and tiers win
  over the superpowers equivalents) and "Writing files under the guard".
- **Advisory format hook (D10).** `format_check.sh`, PostToolUse(Edit|Write), runs
  `runic --check` on a `.jl` file when `runic` is on PATH and reports an unformatted file (exit 2);
  it fails open by design and is silent for read-only agents. `ci.jl format` stays the gate.
- **Lane stats (D11).** `scripts/lane stats [--since ISO]` (one row per dispatch: closed, duration,
  verdict, session denials, idle events) and `scripts/lane handoff` (the HANDOFF open-lanes table);
  read-only. Code in the new `factory/template/scripts/_lane_stats.jl` (T3).
- **Verifier (D8).** New read-only agent `verifier`: runs `evidence.jl <job> -- julia scripts/ci.jl
  <job> --timeout 900` and reports counts from the evidence file.
- **Coverage (D9).** No `permissions.deny` list (it would defeat `FACTORY_ALLOW_T3=1`); each limit
  is in `checks.toml` and CHECK_COVERAGE: host-side hook timeouts allow; `agent_type` comes from
  the host (exact-case; tmux-pane teammates UNVERIFIED); the lead with `FACTORY_ALLOW_T3=1` may
  write below `.git`; a copied gitdir under another name is inert, not refused; the commit guard's
  git calls are unwatched; two crash leftovers in one second may fold out of order.
- **Review.** 22 sub-lane review rounds, 4 critic rounds, an integration review and a
  whole-branch review, each blocker closed with a reproducer quoted RED then GREEN. Spec
  `docs/superpowers/specs/2026-10-27-factory-040-design.md`, ADR
  `adr/0016-harness-fails-closed-and-read-only-agents.md`.
- **Migration** (from 0.3.1, or 0.3.2 once folded on top of it). The sync brings every managed
  file. Then, by hand:
  - `.agents/agent-registry.toml` (seeded): end every `output_format` with `; at most 80 lines`;
    give `reviewer` and `critic` `Write` (Edit stays disallowed) and file_scope
    `.lanes/reports/**`, `.lanes/scratch/<name>/**`, and the verdict/head opening of their
    `output_format`; add `verifier` if wanted. Then `julia scripts/gen.jl`.
  - CLAUDE.md (seeded): carry the `<!-- claim: max_open=N -->` marker on the cap line
    (`check_claims --strict` requires it; the skill no longer has one) and add the "Precedence" and
    "Writing files under the guard" sections.
  - `risk.toml` (seeded): add `scripts/_lane_stats.jl` (`factory/template/scripts/_lane_stats.jl`)
    to the T3 paths.
  - Restart the session so the new hooks (`format_check.sh`, the Monitor matcher) load.
  - Name every reviewer, critic and verifier dispatch: `lane audit --report` fails an unnamed one.
